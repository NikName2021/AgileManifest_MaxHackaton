# Сезон — frontend

Мини-приложение работодателя для сезонного найма в MAX. React + TypeScript + Vite, React Router, MAX UI и MAX Bridge. Рабочее название интерфейса — «Сезон».

## Что готово

- Маршруты обзора, вакансий, откликов, инструкции и настроек; обработка неизвестного URL.
- Адаптивная оболочка: sidebar на компьютере, нижняя навигация на телефоне, safe-area.
- Светлая, тёмная и системная темы; только предпочтение темы сохраняется в localStorage.
- Загрузка Bridge с тайм-аутом и повторной попыткой, управление системной кнопкой «Назад».
- Состояния входа: загрузка, запуск вне MAX, недоступный Bridge, отсутствие настройки сервера, 401, 403, недоступность сети и невалидный ответ.
- Адаптер серверной проверки initData; локальный просмотр без реального входа.
- Строгая проверка типов, ESLint, Prettier, тесты авторизации и Bridge.

Реализованы списки и карточки вакансий, создание и редактирование черновика, публикация,
отклики и смена их статусов, зарплатный бенчмарк. Данные приходят из backend API.
Живая проверка входа, публикации и уведомлений в MAX выполняется после развёртывания;
порядок описан в `../test-data/README.md`.

## Запуск

Node.js 22.22.2+ и npm 10+.

```sh
cd frontend
npm ci
npm run dev
```

Обычно Vite запускается на http://localhost:5173; точный адрес и порт смотрите в выводе команды. После проверки Bridge нажмите «Открыть демо» — откроется интерфейс с явной пометкой. Если CDN MAX недоступен, ожидание занимает до 8 секунд, после чего локальный просмотр всё равно доступен. Backend для этого не нужен.

Остановка — Ctrl+C; повторный запуск — `npm run dev`.

```sh
npm run typecheck
npm run lint
npm test
npm run format:check
npm run build
npm run preview
```

Production preview доступен на http://127.0.0.1:4173. Демо-вход в production выключен независимо от `VITE_ENABLE_DEV_MODE`, поэтому вне MAX отображается приглашение открыть бота. `build/` — результат сборки, в Git не добавляется. Для реального размещения нужен HTTPS и fallback всех путей приложения на `index.html`.

`npm run test:watch` — тесты при изменениях. `npm run format` — форматирование.

## Конфигурация

Для подключения скопируйте `.env.example` в `.env.local` (в PowerShell: `Copy-Item .env.example .env.local`). После изменения env перезапустите Vite или пересоберите production.

| Переменная             | Назначение                                                             | Значение по умолчанию         |
| ---------------------- | ---------------------------------------------------------------------- | ----------------------------- |
| `VITE_API_BASE_URL`    | Адрес backend; в production только HTTPS                               | Текущий origin                |
| `VITE_AUTH_PATH`       | Согласованный путь серверной проверки MAX initData                     | `/api/auth/max`       |
| `VITE_BOT_URL`         | Ссылка на бота на `https://max.ru` или `https://web.max.ru`            | Пусто, ссылка не показывается |
| `VITE_ENABLE_DEV_MODE` | Разрешает кнопку локального просмотра только при `import.meta.env.DEV` | `true` только в dev           |

Все `VITE_*` значения публичны. Токен бота, пароли, серверные ключи и рабочие initData сюда не помещать. `.env.local` и прочие локальные env исключены из Git. `.env.development` и `.env.production` также считаются локальной конфигурацией и не версионируются. Демо включено по умолчанию только при `npm run dev`; его можно отключить через `VITE_ENABLE_DEV_MODE=false`.

Реальный запуск с initData всегда идёт через сервер; отказ входа не переключается на демо. Демо-профиль, вакансии и отклики существуют только в памяти до перезагрузки, запросы к API из него не отправляются. Демо-публикация и демо-отклики — моделирование интерфейса, а не доставка сообщений в MAX. MAX Bridge загружается с внешнего CDN.

## Структура

```text
src/
  app/                 # маршруты, оболочка, граница ошибок
  pages/               # экраны
  features/
    appearance/        # темы
    session/           # вход, состояние сессии, контракт
    vacancies/         # вакансии и API
    applications/      # отклики и воронка
    benchmark/         # зарплатный бенчмарк
  entities/hiring.ts   # доменные поля из ТЗ
  shared/
    api/               # HTTP-клиент, ошибки, отмена и тайм-аут
    max/               # адаптер MAX Bridge
    ui/                # общие элементы
    config.ts          # публичные настройки
  mocks/               # локальная сессия и синтетические данные в памяти
  test/                # окружение тестов
```

Текущий контракт backend описан в [openapi.yaml](../openapi.yaml), порядок проверки — в [test-data/README.md](../test-data/README.md). [INTEGRATION.md](INTEGRATION.md) содержит контекст интеграции; при расхождении сверяйтесь с текущим API и реализацией.

## Ручная проверка

1. Запустить dev, открыть демо. Видна отметка режима; созданные в нём вакансии и демонстрационные отклики не являются реальными данными.
2. Перейти по пунктам навигации, открыть инструкцию, вернуться на главную.
3. Выбрать светлую/тёмную/системную тему; обновить страницу и снова открыть демо — выбор сохранён.
4. Проверить ширины 360, 390, 768 и 1440 px: горизонтальной прокрутки нет, нижнее меню не закрывает содержимое.
5. Открыть `/settings` напрямую; после входа сохраняется выбранный маршрут. Неизвестный URL показывает 404 с возвратом на главную.
6. Production preview: демо-кнопки нет; без бота нельзя попасть в рабочий кабинет.
7. После развёртывания пройти живой сценарий из `../test-data/README.md` в мобильной и веб-версии MAX.
