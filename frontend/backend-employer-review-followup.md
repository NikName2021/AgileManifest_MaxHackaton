# Кабинет работодателя: ссылка для связи в MAX

## Что осталось от пункта 6.5 PDF

В карточке отклика реализованы копирование контакта и открытие оставленной кандидатом ссылки MAX через `WebApp.openMaxLink`. Если контакт — телефон или e-mail, показано соответствующее действие. При ошибке буфера обмена контакт доступен для ручного копирования.

Для кнопки «Написать в MAX» независимо от типа контакта нужен подтверждённый адрес профиля/диалога кандидата. Сейчас `backend/src/server.ts` возвращает `candidate.maxUserId`, `displayName` и `phone`, но не URL. Формировать адрес профиля из числового ID без документированного правила нельзя.

## Предлагаемый контракт

Добавить nullable `candidate.maxContactUrl` в ответы списка откликов, откликов по вакансии и изменения статуса. Значение — настоящая HTTPS-ссылка MAX, предоставленная пользователем либо полученная документированным способом. Если адрес неизвестен, возвращать `null`. Не отдавать служебные ID чатов и не собирать предполагаемые URL из `maxUserId`.

После появления поля фронтенд сможет всегда предпочитать эту ссылку для «Написать в MAX»; при `null` останется текущее действие по оставленному контакту. Ограничения доступа к откликам сохраняются.

Документация: [MAX Bridge — openMaxLink](https://dev.max.ru/docs/webapps/bridge). Метод принимает готовый URL; в этой документации не описано преобразование числового ID в адрес профиля.

## Проверка после внедрения

- У кандидата с телефоном и `maxContactUrl` доступны копирование телефона и открытие MAX.
- При `null` нет неработающей кнопки MAX.
- Некорректные протоколы и домены не открываются.
- Ссылка проверена на реальном устройстве в MAX; локальная демо-проверка не подтверждает доставку сообщений.

Остальные изменения из приложенного контракта используют уже существующие API категорий, бейджей, компании, статистики вакансий и каналов.
