# Сезон — frontend

Основа мини-приложения работодателя для сезонного найма в MAX. React + TypeScript + Vite, React Router, MAX UI и MAX Bridge. Рабочее название интерфейса — «Сезон».

## Что готово

- Маршруты обзора, вакансий, откликов, инструкции и настроек; обработка неизвестного URL.
- Адаптивная оболочка: sidebar на компьютере, нижняя навигация на телефоне, safe-area.
- Светлая, тёмная и системная темы; только предпочтение темы сохраняется в localStorage.
- Загрузка Bridge с тайм-аутом и повторной попыткой, управление системной кнопкой «Назад».
- Состояния входа: загрузка, запуск вне MAX, недоступный Bridge, отсутствие настройки сервера, 401, 403, недоступность сети и невалидный ответ.
- Адаптер серверной проверки initData; локальный просмотр без реального входа.
- Строгая проверка типов, ESLint, Prettier, тесты авторизации и Bridge.

Это объединённый этап setup + MAX shell. Списки вакансий и откликов пока обозначены как будущие разделы: они не изображают данные из backend. Форма вакансии, публикация, рабочая воронка и бенчмарк относятся к следующим feature-веткам. Настоящий вход в MAX ожидает данных бота и согласованного auth-метода.

## Запуск

Node.js 22.12+ (проверялось на 22.23.2), npm 10+.

```sh
cd frontend
npm ci
npm run dev
```

Адрес: http://127.0.0.1:5173. Порт фиксирован; при занятости Vite завершится с ошибкой. После проверки Bridge нажмите «Открыть демо» — откроется интерфейс с явной пометкой. Если CDN MAX недоступен, ожидание занимает до 8 секунд, после чего локальный просмотр всё равно доступен. Backend для этого не нужен.

Остановка — Ctrl+C; повторный запуск — `npm run dev`.

```sh
npm run typecheck
npm run lint
npm test
npm run format:check
npm run build
npm run preview
```

Production preview доступен на http://127.0.0.1:4173. Демо-вход в production выключен независимо от `VITE_ENABLE_DEV_MODE`, поэтому вне MAX отображается приглашение открыть бота. `dist/` — результат сборки, в Git не добавляется. Для реального размещения нужен HTTPS и fallback всех путей приложения на `index.html`.

`npm run test:watch` — тесты при изменениях. `npm run format` — форматирование.

## Конфигурация

Для подключения скопируйте `.env.example` в `.env.local` (в PowerShell: `Copy-Item .env.example .env.local`). После изменения env перезапустите Vite или пересоберите production.

| Переменная             | Назначение                                                             | Значение по умолчанию         |
| ---------------------- | ---------------------------------------------------------------------- | ----------------------------- |
| `VITE_API_BASE_URL`    | Адрес backend; в production только HTTPS                               | Текущий origin                |
| `VITE_AUTH_PATH`       | Согласованный путь серверной проверки MAX initData                     | Пусто, вход не настроен       |
| `VITE_BOT_URL`         | Ссылка на бота на `https://max.ru` или `https://web.max.ru`            | Пусто, ссылка не показывается |
| `VITE_ENABLE_DEV_MODE` | Разрешает кнопку локального просмотра только при `import.meta.env.DEV` | `true` только в dev           |

Все `VITE_*` значения публичны. Токен бота, пароли, серверные ключи и рабочие initData сюда не помещать. `.env.local` и прочие локальные env исключены из Git. `.env.development` и `.env.production` также считаются локальной конфигурацией и не версионируются. Демо включено по умолчанию только при `npm run dev`; его можно отключить через `VITE_ENABLE_DEV_MODE=false`.

Реальный запуск с initData всегда идёт через сервер; отказ входа не переключается на демо. Демо-профиль существует только в памяти до перезагрузки, запросы к API из него не отправляются. Шрифт Manrope поставляется локально с приложением, без Google Fonts/CDN. Единственная runtime-зависимость от внешнего CDN — MAX Bridge.

## Структура

```text
src/
  app/                 # маршруты, оболочка, граница ошибок
  pages/               # экраны
  features/
    appearance/        # темы
    session/           # вход, состояние сессии, контракт
  entities/hiring.ts   # доменные поля из ТЗ
  shared/
    api/               # HTTP-клиент, ошибки, отмена и тайм-аут
    max/               # адаптер MAX Bridge
    ui/                # общие элементы
    config.ts          # публичные настройки
  mocks/               # только локальный демонстрационный профиль
  test/                # окружение тестов
```

Граница с Bot Gateway, модель backend из ТЗ, предлагаемый auth-контракт и будущие API-методы описаны в [INTEGRATION.md](INTEGRATION.md). Неподтверждённые API-методы не вызываются.

## Ручная проверка

1. Запустить dev, открыть демо. Видна отметка режима; нет выдуманных вакансий и откликов.
2. Перейти по пунктам навигации, открыть инструкцию, вернуться на главную.
3. Выбрать светлую/тёмную/системную тему; обновить страницу и снова открыть демо — выбор сохранён.
4. Проверить ширины 360, 390, 768 и 1440 px: горизонтальной прокрутки нет, нижнее меню не закрывает содержимое.
5. Открыть `/settings` напрямую; после входа сохраняется выбранный маршрут. Неизвестный URL показывает 404 с возвратом на главную.
6. Production preview: демо-кнопки нет; без бота нельзя попасть в рабочий кабинет.
7. При подключении настоящего бота пройти checklist из INTEGRATION.md на мобильном и веб-MAX.

## Git

Код этого этапа — в одной ветке `feature/frontend-foundation`. Только локальные коммиты; отправка в удалённый репозиторий не выполняется. `node_modules`, `dist`, локальные env, отчёты проверок и временные файлы в коммит не входят. Папка `tmp` не используется.
